# Live Coach v2: проверка перед выпуском

Новый Android snapshot имеет `snapshot_schema_version=2`. Тренировки, созданные после обновления,
передают `decision_mode=V2` и полный `original_plan`; ранее начатые тренировки передают
`decision_mode=LEGACY` и `original_plan.complete=false`. Backend закрепляет план и режим при
первом принятом snapshot и отклоняет их последующую замену. Две карточки пользователю не
публикуются.

## Теневое сравнение

Положить обезличенные snapshots (`*.json`, корневой объект snapshot либо `{ "snapshot": ... }`)
в локальную директорию и запустить:

```bash
COACH_EPISODES_DIR=/path/to/anonymized-episodes ./gradlew test \
  --tests '*CoachEpisodeReplayTest' --rerun-tasks
```

Тест считает старое и новое решение без записи в сессию, журнал, предложения или чат.
`build/reports/coach-v2-shadow/decisions.json` содержит только порядковый номер эпизода,
тип решения, код причины и число операций. Перед выпуском разобрать все расхождения для
запланированного снижения повторов, короткого отдыха, неизвестного RIR, разминки, короткой
истории, боли, нехватки времени, оборудования и ранее отклонённого предложения. Если эпизодов
нет, тест пропускается; это не является успешным сравнением.

## Метрики после включения

Считать отдельно по `snapshot->>'decision_mode'`. Источник вопросов — `coach_questions`,
предложений — `coach_intervention_proposals` и `coach_runs` с `result.kind=proposal`, исходов —
`coach_intervention_proposals.status` и `coach_run_receipts.status`. Журнал Android отправляет
событие `payload.kind=undo` после применения отмены.

- Вопросы до полезного решения: число `ANSWERED` вопросов на тренировку до `APPLIED`
  предложения; считать также тренировки без применённого предложения, чтобы не скрыть
  бесполезные вопросы.
- Устаревшие и отклонённые пакеты: доли `STALE` и `REJECTED` среди всех терминальных исходов,
  отдельно для структурированных предложений и model runs.
- Повторы: более одного показанного предложения с тем же `sourceSetId` в одной тренировке после
  отказа или применения.
- Отмены: число событий `undo` после `APPLIED` в той же тренировке; интервал между событиями
  учитывать по `coach_journal.created_at`.

После анализа эпизодов и теста цепочки Android → backend → подтверждение с доступным Docker
выпускать новый путь для новых тренировок. Ранее начатые тренировки остаются в `LEGACY`.
