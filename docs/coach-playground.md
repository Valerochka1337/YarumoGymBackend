# Локальный Coach Playground

Запуск из корня репозитория (JDK 21 и работающий Docker):

```bash
./scripts/coach-playground.sh
```

Открыть **http://localhost:18081/dev/coach/**. В «Настройках модели» указать HTTPS URL
OpenAI-совместимого Chat Completions провайдера, имя модели с поддержкой function tools
и API-ключ. Нажать «Сохранить и подключить», затем отправить сообщение.
Сохранение проверяет формат настроек; доступность провайдера проверяется первым запросом.
Запросы к настоящей модели оплачиваются из баланса провайдера.

Скрипт создаёт отдельный PostgreSQL `gym_playground` на порту 15433, локальные секреты
в игнорируемом `.env.playground` и запускает Spring с профилем `playground` на порту 18081.
Обычная `.env` не используется. Настройки модели и зашифрованный ключ сохраняются
в отдельном Docker volume. Сохраняйте `.env.playground` между запусками: он нужен
для расшифровки ключа. Пользователь, каталог из четырёх упражнений и три исторические
тренировки создаются автоматически. Вход и копирование токенов не нужны.

## Проверка сценария

1. Выбрать сценарий: обычная тренировка, тяжёлый подход или осталось пять минут.
   Нажать «Начать заново» для загрузки выбранного сценария.
2. Менять вес, повторы, RIR, ощущения и отметку выполнения подхода.
   У выполненного подхода вес и повторы редактируют фактический результат.
3. Написать coach. Ответ приходит потоком; предложение показывает изменения
   и позволяет посмотреть полный пакет операций, принять или отклонить его.
4. Для инициативных проверок включить «Инициатива coach». Стенд отправляет
   полные снимки после изменений и поддерживает свежесть активной сессии.
   Автоматические проверки используют модель по умолчанию из настроек;
   выбор модели над чатом относится к ручным сообщениям.
5. Изменить подход во время генерации: старое предложение станет `STALE`.
6. Нажать «Отключить поток», затем «Подключить поток»: worker продолжает работать,
   события восстанавливаются с последнего номера. Перезагрузка той же вкладки
   сохраняет тренировку, задачи и очередь подтверждений.
7. «Скачать сеанс» экспортирует снимок, сообщения, результаты, очередь и журнал
   этапов без API-ключа и access-токена. Это диагностический файл, импорт пока не реализован.

«Начать заново» завершает старую сессию, отменяет активные задачи и создаёт новую
тренировку. Каталог и история в БД остаются исходными: стенд не записывает в них
результаты симулируемой тренировки. Старые coach runs остаются в локальной БД.

Состояние интерфейса хранится в `sessionStorage`: перезагрузка его сохраняет,
закрытие вкладки — нет. Для разных сценариев открывайте независимые новые вкладки;
не дублируйте вкладку с уже активной тренировкой (браузер может скопировать её состояние).

## Что именно проверяется

Используются обычные `/v1/coach/runs`, SSE events, sessions, receipts и реальный
`CoachRunExecutor` / `CoachRunTools` / `CoachRunContext`. Сценарного провайдера нет.
`no_change` виден в стенде как диагностическая отметка, хотя в Android он должен быть тихим.
Журнал показывает этапы и имена инструментов; сырой запрос провайдеру и его внутренние
рассуждения интерфейс не раскрывает.

Применение операций — локальная имитация Android: атомарное обновление снимка,
проверка revision/contextVersion/срока предложения и доставка receipt. При неподдерживаемой
операции кнопка применения отключается. Это не проверка Android Room, foreground-сервиса
или синхронизации клиента. Отдых отображается как состояние без живого отсчёта;
поле оставшегося времени меняется вручную. Истечение предложения использует реальное время.

UI и bootstrap/settings API доступны только с профилем `playground`, привязкой к loopback
и отдельной локальной БД. Никаких новых маршрутов авторизации в основном API нет.
Профиль и скрипт не предназначены для размещения за внешним reverse proxy.

Остановить Spring: Ctrl+C. Остановить отдельную БД без удаления данных:

```bash
docker compose -f infra/compose.playground.yaml stop
```

Проверки:

```bash
node --test src/test/js/coach-playground.test.cjs
./gradlew test --tests '*CoachPlayground*' --tests '*CoachRunIntegrationTest' --tests '*CoachRunExecutorTest'
```

Для Colima используются те же `DOCKER_HOST` и `TESTCONTAINERS_RYUK_DISABLED=true`,
что описаны в README. Автотесты не тратят баланс модели. Качество реального диалога
проверяется вручную после настройки провайдера.

### Поток всей тренировки

Новые сообщения стенда отправляются через `sessions/{workoutId}/messages` со снимком.
SSE `sessions/{workoutId}/events` остаётся подключённым между ответами; общий курсор сохраняется
в sessionStorage. При недоступном потоке используется восстановительный опрос. Heartbeat снимка —
60 секунд. Автоматические ошибки, черновики и `no_change` в чате не показываются. Ранее сохранённые
запросы `/runs` продолжают доставляться в исходном формате.

### Совместимость раннего варианта миграции 022

Если playground применил 022 во время разработки, исходный checksum был
`9:94adf1dec72cd01e3aea086dc4c5c9d4`. Исходное содержимое 022 восстановлено;
промежуточный вариант `9:e6359f6df0e93593ba68ddd6229dba2d` также явно разрешён.
Отдельная миграция 023 добавляет `coach_session_events.response`, если колонки ещё нет.
Обычный запуск `./scripts/coach-playground.sh` обновляет оба варианта базы с сохранением
задач и событий. Сбрасывать базу или очищать checksums не требуется.
